## DEMO-FIX-001：零执行状态

触发：空执行集合，所有用例都等待人工，或全部因为非功能类型/缺脚本而跳过时，原逻辑只有“全缺脚本”会返回 not_executed，其余可能显示绿色 Passed。

### 判定与验收

- 有 failed 或 error 回执：保持 failed。
- 有 passed 回执，且没有 failed/error：保留现有实际执行结果；跳过、待人工明细仍单独显示，不进入通过率分子。
- 没有任何已执行回执：返回 not_executed，包括空批次、全待人工、全非功能跳过及不同未执行原因混合。
- 报告的实际执行数为零时，显示 Not executed，不展示通过率；说明具体跳过/待人工/未运行数量。
- 运行页不把所有未执行原因都归为“缺脚本”，人工待执行仍能进入 Record result。
- 本次修复从新运行的结束判定生效，不改写旧执行记录或不可变报告，不修改已应用 SQL 迁移。
- 批次标签描述其结束时的结果；之后补录人工结果仍保留原批次报告快照，最新结果可另生成版本报告。这一项未新增“人工补录后重算旧批次”机制。

### 实现

后端统一 run_outcome 的零执行判定。报告列表、报告详情复用 nothingExecuted/passRateText/passRateNote；运行页使用与原因无关的未执行说明。沿用已有 not_executed 状态，无需增加数据迁移。

### 验证记录

- 测试先行：新增/修订用例先观察到后端 6 项、前端 6 项失败，再修复实现。

- 前端：34 个测试文件、116 项通过；eslint、TypeScript 和生产构建通过。
- Ruff 和修改文件的格式检查通过。
- 完整后端：453 项通过、1 项跳过（Windows 不适用的 POSIX 文件权限检查），耗时 575.50 秒。通过项中含 42 项演示被测系统测试，不能把它们等同平台功能完成。
- 包含 3 项真实 Chromium 端到端测试，均通过。模型使用测试替身，不代表真实模型效果已验收。

## DEMO-FIX-002：执行版本追溯

触发：用例绑定某一 commit 后，执行器直接运行工作目录，结果却记录运行结束时的 HEAD。未提交修改、辅助文件变化或运行期间的新提交都可能使记录版本与实际运行内容不同。

### 判定与验收

- 有绑定版本时，从该固定完整 commit 独立检出整个仓库再运行，包括 conftest、helpers、pytest 配置等已跟踪文件。
- 即使原工作目录存在未提交修改、更新提交或文件被删除，也不替换已绑定版本；不覆盖、提交或切换用户原工作区。
- 版本只解析一次。运行期间原仓库的新提交不改变执行目录或结果记录的 code_commit。
- 历史未绑定 commit 的用例，以开始执行时解析到的 HEAD 创建固定副本，并记录实际完整 SHA，不继承“已绑定脚本”的验证假设。
- 指定的绑定 commit/脚本不可用时明确失败，不回退到当前 HEAD 或当前文件。只读代码查看也遵循这一规则。
- 独立临时目录在正常返回和异常时清理；临时 Git 对象不与原仓库硬链接或共用替代对象库。
- 自动化面板解释“执行绑定版本”；要运行本地修改，应先提交并重新绑定。

### 实现与边界

TestRepo.execution_snapshot 使用本机 Git 克隆（无网络拉取），独立复制对象并检出固定 commit；ExecutionService 在此副本调用现有 pytest 执行器。结果记录解析出的固定版本，不再读取运行结束时的原仓库 HEAD。执行器和人工调试共用这一规则；AI 生成阶段的未提交候选自检继续按原候选工作流处理。

副本仅包含 Git 跟踪的内容，忽略文件/未提交的辅助数据不会自动带入。test_data、环境地址和平台已安装依赖仍按既有执行器注入；本项固定的是仓库源码版本，不是完整操作系统/依赖/被测系统快照。

### 验证记录

## DEMO-FIX-003：当前流程步骤入口

触发：顶部主流程条的高亮步骤代表流程建议的下一步，并不一定是用户正在查看的页面。Ant Design Steps 的 onChange 只在选择不同步骤时触发，导致用户从其他页面点击这个高亮步骤没有反应。

### 判定与验收

- 点击高亮步骤时进入该步骤的页面，保留目标地址中的版本和标签页参数。
- 聚焦步骤后使用 Enter 或空格也能进入。
- 已完成、待处理步骤保留导航；一次操作只增加一次页面历史，返回一次即可回到原页。
- 全流程完成后，步骤仍可进入；高亮状态继续反映流程进展。
- Next 仍使用独立动作，包括 Run tasks 打开批量运行弹窗的既有行为。

### 实现

只给当前步骤补上 item onClick，其余步骤沿用 onChange。避免同时为所有步骤添加第二次导航；保留 Steps 自带的焦点、Enter 和空格处理，无需嵌套按钮或改写进度计算。

### 验证记录

- 测试先行：鼠标、Enter、空格三项导航测试先失败，实际地址仍为原页；另三项既有导航行为通过。
- 定向前端：15项通过，覆盖步骤导航、历史返回、主流程展示和批量运行弹窗。
- 完整前端：35个文件、122项通过。
- 完整后端：464项通过、1项跳过（Windows不适用的POSIX权限检查），耗时672.10秒。通过项中含42项演示被测系统测试和3项真实Chromium端到端测试。
- eslint、TypeScript、生产构建、Ruff及git diff --check通过。
- 结构化结果：[DEMO-FIX-003验证记录](demo-fix-003-verification.json)；本地原始JUnit：`runtime/demo-fix-003-backend.xml`。

本项未修改后端执行逻辑或数据库迁移。回归仅使用隔离测试数据库，模型使用测试替身，不代表真实模型效果已验收。

## DEMO-FIX-004：最近运行入口及运行中提示

触发：从运行详情离开后，版本页的任务列表缺少回到该次运行的直接入口，也看不到哪些任务还在运行。

### 验收约定

- 每个任务展示最近运行的时间、状态、已处理用例数/该批次总数及详情链接。尚未运行时显示 Never run yet；排队时显示 Awaiting start，避免把尚未确定的总数显示为执行进度。
- 策略页签顶部（策略表单之前）显示 running/queued 数量和各任务的运行链接；全部结束后提示消失，历史入口仍保留。
- 页面每5秒刷新任务列表，能够发现计划调度或其他页面启动的任务，也能够发现完成状态。沿用查询库默认的后台窗口暂停行为。
- 初次加载失败不显示为空任务列表；显示可重试提示。刷新失败保留旧数据并明确其可能过期，警告置于顶部运行提示之前，重试后恢复。
- 没有任务时保留原有新建任务入口。宽任务表格在自身区域横向滚动，链接可通过键盘访问。
- 当前项只补版本页 Test strategy & tasks 区域，不新增执行引擎或改写历史结果。

### 实现与数据约定

任务列表接口新增可空 latest_run 摘要。使用同一条SQL为每个任务关联最新运行（created_at降序、id降序保证同时间下选择稳定），按版本隔离；不从带全局数量上限的最近运行列表推断，避免频繁运行的任务挤掉其他任务的记录。未增加逐任务HTTP请求。

运行计数提取为共享函数，供运行详情、运行历史及任务摘要使用；已处理数包含原有终态回执，不能解释为全部实际执行或全部通过。排队和执行中的状态取运行记录，不用任务可编辑状态代替运行结果。

### 验证记录
