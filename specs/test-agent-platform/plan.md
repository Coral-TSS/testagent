## 3 后续团队演进

1. TEAM-019：SUT 认证与凭据使用链路、并发编辑 expected_revision、按 SUT 授权设计。已有账号不能代替这些能力。
2. INTEGRATION-020：每 SUT 测试仓远程同步/分支/PR review，外部缺陷系统对接。缺陷对接按演示反馈提升为 P1 规划项，先选择一个目标系统并定义幂等、重试和状态归属。
3. RUNNER-021：隔离执行器、远程 Runner、并行与多实例；依赖代码分发、授权、幂等回执和取消协议，不直接放开当前单实例锁。
4. I18N-022：英文界面基础上的中文资源与切换；Agent 输出语言仍独立设置。可按国内试用反馈提前。

正式 OWL/RDF、源码解析、官方 Playwright Test Agents 适配继续列研究候选，不引入当前运行栈。

## 4 完成定义

- 新行为先有能复现问题的测试；可逆文档调整做一致性检查即可。数据库验证使用 `_test` 库隔离 schema。
- 涉及产品代码时执行适合变更的定向与全量检查；前端实际命令为 `npm --prefix web test`、`npm --prefix web run lint`、`npm --prefix web run build`。后端 pytest、Ruff；记录 skip 原因。
- 浏览器/E2E 期间固定前端产物，不并行重建；若最终构建变化，复验 E2E。
- AI 假模型测试只证明编排/契约；真实模型效果单独记录。连接成功不等于测试设计质量合格。
- 不改已应用迁移；不打印或提交秘密；不直接改不可变报告以美化结论。
- 更新 spec/详细设计/任务/验证记录，提交 develop，按既有授权推 GitHub 并核对远端；生产部署单独处理。
- 仓库规格为主，外部规格目录只作同步镜像；历史原始演示记录不被改写。
