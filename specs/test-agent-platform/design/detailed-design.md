# TestAgent 详细设计 v1.2

2026-11-09；源码基线 `f8eb361`。本文件补齐“架构到可验证行为”的契约，引用仓库实际服务。除 §7 后续设计外，均为现有实现说明。

## 1 自动化与自检

1. 选定用例/环境→环境预检；不可达不调用模型、不消耗自检次数，未绑定用例为 env_unavailable。
2. automate_case 获得单个目标测试文件写权限；模型生成代码并运行自检。
3. 自检通过：提交脚本，绑定 code_path/code_commit，记录来源。人工 Ready 仍是另一个操作。
4. 脚本问题/未验证：保留草稿提交和失败证据，needs_fix。需求支持的断言不一致：sut_mismatch，避免自动把预期改成实际行为。
5. 人确认疑似系统问题时，confirm-sut-issue接受bind_and_record或record_only；认定脚本问题走单独的mark_script_issue服务操作。绑定或只记失败保留失败执行，可选建缺陷。人工绑定已有脚本也有独立入口；不能将“AI自动绑定需自检通过”误写成“任何绑定都要求自检通过”。

实现：`services/automation.py`、`failure_classify.py`、`integrations/pytest_report.py`。来源完整性与人工确认在 API/服务测试中验证；真实模型判断准确性独立验收。

## 2 执行及报告口径

| 条件 | 用例结果 | 对统计的影响 |
|---|---|---|
| pytest/工具断言实际成功 | passed | 已执行及通过 |
| 断言不满足 | failed | 已执行，保留期望/实际 |
| 工具/脚本/环境错误 | error（具体预检也可终结批次） | 若存在 error 用例回执，计已执行；原因分开显示 |
| 人工任务尚未提交 | blocked/awaiting_human | 不计通过率分母 |
| 自动化任务无脚本 | skipped/no_script | 单列测试准备缺口 |
| 非功能类型 | skipped | 不伪装成通过 |
| 没开始的用例 | 未执行计数 | 不虚造执行回执 |

正常批次结束时 `run_outcome`：存在 failed/error → failed；否则没有 passed → not_executed；否则 passed。取消/编排异常另由对应分支终结，不用这个函数抹掉原因。passed 批次仍可能有跳过/待人工，必须展示完整计数，不等于全覆盖。

版本报告取每用例最新执行；报告是不可变快照，历史报告不会被列表修复重新统计覆盖。状态、failure_kind、suspected_cause 不互相替代；AI 摘要不改变统计。

## 3 Git 版本锁定

生成提交和执行提交都用完整 SHA；正式执行进入 execution_snapshot，先解析绑定 SHA，再独立 clone/checkout 整个本地仓，执行该版本测试文件和辅助文件。手工工作区的更改、新 HEAD 不影响已绑定版本。绑定缺失报错；没有绑定的旧用例才固定当前 HEAD。finally 清理临时检出。代码查看器也不能在绑定不存在时展示新 HEAD 冒充绑定版本。

已有测试覆盖旧版本 fixture、工作树脏文件、不可用 SHA、清理与实际记录的一致性，见 `tests/integrations/test_execution_snapshot.py`。远程 fetch/评审分支、执行器隔离不在现实现内。

## 4 Ready、规则绑定与运行进度

状态写入→事务提交→case 事件→TaskBindingService 匹配同系统开放版本任务→读取实际 task_case 关系→返回反馈。列表间 AND/列表内 OR；人工行优先、排除名单不自动加回；运行中/归档任务不改。

ReadyTaskFeedback 展示已关联任务/版本/来源及不加入原因，批量汇总成功、已就绪、跳过和失败。事件失败不回滚已经保存的 Ready，也不谎称关联成功。重新加载仍能查看实际关系，GET 不修改绑定。

任务列表显示最近批次和处理数；排队/运行中提示可跳回运行页。轮询发现调度启动和结束；失败保留上次内容且说明可能过期。系统/版本变更必须更新查询键，不能跨范围复用结果。

## 5 模型建议与视图

来源为 requirement/openapi/model_rule/ai_inferred；需求引用须与原文核对。AI 推断不默认接受且需要采纳依据；已有节点/API、同批、待审及已拒建议用于去重。关系建议需人审。

实体/动作/字段/ModelLink 是共享模型事实；图和列表读取同一资源。当前字段支持 display_name，但实体引用各处的显示名契约尚不统一（UX-009）；不要为界面修正改 UUID、name、API 参数或关联键。

## 6 共享界面契约

- ListTable 默认每页 50；已有历史每页 10 保留。正文 max-height=min(52vh,560px)，区域可键盘聚焦/滚动。模型审阅内嵌字段区域为 min(32vh,320px)。客户端分页不意味着后端总量无限可达。
- 缺陷500、报告200、最近运行50、Agent轨迹100、用例执行历史100、任务历史100、纠错200、记忆500：计数说明最近已加载和上限，不能宣称数据库总数；最近运行接口 limit 允许1–200。首次未知、失败不可用、缓存刷新失败分开显示。
- 系统/版本条件先于 LIMIT，二者交集；分页编辑/删除以稳定记录身份定位。打印报告/审阅关闭分页和高度限制，保留全部已取得快照行。
- ReadingDrawer 桌面默认视口60%，480px至视口减48px；低于768px全宽、无拖动把手。Pointer Events 抬起才保存，取消/视口变化撤回本次拖动；键盘左右每次32px、Home/End边界、Enter恢复默认。每类宽度独立，禁用/无效 localStorage 降级。
- ExpandableDescription 超过160个Unicode码点提供预览/全文提示/展开；保留换行，按钮不触发行导航；更换文本重置展开。需求/节点详情表单使用独立名称避免隐藏表单重复id；宽度调整不隐式提交。
