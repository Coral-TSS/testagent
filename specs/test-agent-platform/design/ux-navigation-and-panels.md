# 导航与抽屉/表单交互

2026-11-21。相对 `develop` `b5795dd`。本文只约定本轮要改的导航和编辑面板，不实现路线图里的其他项。

## 1. 问题

- 选中被测系统后，左侧会多出一组以系统编号命名的一级菜单（概览、模型、模型评审、API 注册表、版本、用例库），顺序和主流程不一致，策略、任务没有自己的入口。
- 另有一级「测试用例」，和系统内的用例库是同一个页面，只多一个系统下拉。
- 菜单高亮只看 pathname，版本页、任务页、执行详情经常没有任何高亮。
- 模型节点用带遮罩的抽屉，字段、关系、输入输出再叠一层对话框；保存有的立刻提交，有的要点右上角「保存」。
- 图谱高度写死 600，节点不能拖线建关系（`nodesConnectable={false}`）。

## 2. 左侧导航

侧栏固定宽度 240。一级项目不随是否选中系统而把「全部被测系统」换成流程菜单。详见 `nav-versioned-model-supply-chain-demo.md` 第 1 节；与本节冲突时以该文档为准。

一级顺序：

1. **全部被测系统**（独立一级，始终可点）→ `/suts`。这是管理系统、进入某个系统的入口，不再嵌在可变形的子菜单里，也不再在选中系统后被挤到底部。
2. **当前系统区**（仅当已经进入某个被测系统时显示，不是会把第 1 项吃掉的一级）：
   - 顶部是**当前系统切换**和**当前版本切换**，与顶栏选择器同步。从这里就能换系统、换版本。
   - 其下按工作流程排列，全部属于当前系统（及当前版本，若该页依赖版本）：
     - 概览 → `/suts/:sutId`
     - **建模**（子项，跟随当前版本；没有版本时三项都禁用，提示「请先创建版本」）
       - 模型图谱 → `/versions/:versionId/model`
       - 模型评审 → `/versions/:versionId/review`
       - API 注册表 → `/versions/:versionId/apis`
     - 版本与需求 → `/versions/:versionId`
     - 策略 → `/versions/:versionId/strategy`
     - 任务 → `/versions/:versionId/tasks`
     - 用例 → `/suts/:sutId/cases?version_id=`
     - 执行 → `/executions?sut_id=&version_id=`
     - 缺陷 → `/defects?sut_id=&version_id=`
   - 版本与需求、策略、任务、建模在没有版本时禁用，提示「请先创建版本」。创建版本仍从概览的「管理版本 / 新建版本」和步骤条进入 `/suts/:id/versions`。
   - 未进入任何系统时不显示当前系统区，建模也不作为孤立的一级菜单。
3. **执行**、**缺陷**：保留跨系统的一级入口（不带系统参数，页面内可筛选，默认全部系统）。当前系统区里的同名项是当前系统的范围。
4. **测试报告**：仍是一级，跨系统，页面内筛选。
5. 分组 **人员**（人员、人员统计）、**Agent**（设置、运行、工具）、**用户**（仅管理员）。

去掉一级「测试用例」。`/cases` 若查询串里有 `sut` 或 `sut_id`，重定向到该系统的用例页并保留 `version_id`；否则到 `/suts`。`/cases/:caseId` 不变。旧的 `/suts/:sutId/model`、`/review`、`/apis` 重定向到当前版本的对应页；没有版本则回到概览并提示先创建版本。

顶栏的系统、版本选择器保留。切换系统时尽量留在同一类页面（用例、执行、缺陷、报告）；版本页（含建模）因为版本号不能沿用，回到新系统的概览。切换版本时，若当前就在版本、策略、任务或建模页，则换到同一段的新版本。

### 2.1 路由

| 路径 | 页面 |
|---|---|
| `/versions/:versionId/model` | 模型图谱（当前版本） |
| `/versions/:versionId/review` | 模型评审（当前版本） |
| `/versions/:versionId/apis` | API 注册表（在当前版本上下文打开；接口仍按系统登记） |
| `/versions/:versionId/strategy` | 策略（原策略页签上半） |
| `/versions/:versionId/tasks` | 任务列表与新建任务 |
| `/suts/:sutId/model`、`/review`、`/apis` | 重定向到当前版本的对应页；没有版本则回到概览 |
| `/versions/:versionId?tab=strategy` | 重定向到 `/strategy`，其余查询参数保留 |
| `/versions/:versionId?tab=tasks` | 重定向到 `/tasks` |
| `/cases` | 重定向，见上 |

版本页仍保留需求、模型建议、用例、变更日志页签。菜单里的「用例」指向系统用例库（带当前版本），版本页的用例页签继续可用，高亮也算「用例」。

### 2.2 高亮

按流程阶段选中，不按原始 pathname。选择函数放在 `web/src/app/navMenu.ts`。

| 阶段键 | 命中 |
|---|---|
| `sut-overview` | `/suts/:id` |
| `sut-requirements` | `/suts/:id/versions`，`/versions/:id` 及其需求、建议、日志、需求抽屉 |
| `sut-strategy` | `/versions/:id/strategy` 或旧的 `?tab=strategy` |
| `sut-tasks` | `/versions/:id/tasks`、`/tasks/:id` |
| `sut-cases` | `/suts/:id/cases`、`/cases/:id`、版本页 `?tab=cases` |
| `sut-executions` | 执行列表带了 `sut_id`，或执行/运行详情且已解析出当前系统 |
| `global-executions` | `/executions` 不带系统，或详情尚不知道系统 |
| 缺陷 | 与执行同一规则，键为 `sut-defects` / `global-defects` |
| `model-graph` / `model-review` / `model-apis` | `/versions/:id/model`、`/review`、`/apis`（旧的 `/suts/:id/model` 等在重定向前也算） |
| `global-reports` | `/reports` 与报告详情 |
| `sut-list` 及人员、Agent、用户 | 对应列表页 |

同一阶段只亮一项：带了当前系统就亮子菜单，看全部系统就亮一级。

### 2.3 步骤条与面包屑

后端 `progress()` 的步骤键和顺序不变：`sut, model, requirements, strategy, tasks, cases, runs, results`。只改路径，让步骤条和菜单落到同一页：

- 策略 → `/versions/{id}/strategy`
- 任务 → `/versions/{id}/tasks`
- 用例 → `/suts/{sutId}/cases?version_id={id}`
- 尚无运行时，「执行任务」的回退路径改为任务页；`kind=run_tasks` 仍就地打开执行对话框。

任务面包屑由「测试策略与任务 → `?tab=strategy`」改为「任务 → `/versions/{id}/tasks`」（kind 改为 `tasks`）。有版本的用例面包屑改为系统用例库。对象引用里测试策略的路径一并改掉（`services/labels.py`）。

步骤条标题顺序仍是被测系统 → 模型 → 需求 → 策略 → 任务 → 用例 → 执行 → 结果。模型在菜单里归到当前系统区的「建模」，路径是 `/versions/{id}/model`；结果在菜单里是缺陷和测试报告。两边的共同阶段顺序一致。

## 3. 共享组件

不引入新依赖，只用 antd 6。

### 3.1 `AppModal`（`web/src/components/panel/AppModal.tsx`）

宽度只有三档：`sm` 520、`md` 720、`lg` 960。标题下可放一行说明。保存类对话框的主按钮文案是「保存」，取消是「取消」。确认删除、生成、重置这类动作保留各自的动词，不用「确定」冒充保存。

### 3.2 `EditableTable`

表头固定。主列直接是输入控件，「+ 添加一行」在表下追加一行，不弹窗。单位、示例、数据库列名、格式、说明等少用属性放在可展开行。空表用 `EmptyState`，主按钮就是添加一行。删除用图标按钮，并带「删除 {名称}」的可读名称。分页仍用现有列表的每页 50 条，避免长参数表丢行。

### 3.3 `SideDetailPanel`

停靠在内容右侧，**没有遮罩**，不是 `role="dialog"`。默认宽 520。左侧拖拽和方向键沿用 `ReadingDrawer` 的宽度记忆（同一个 `testagent:drawer-width:<kind>`，抽出 `useRememberedWidth`）。窄屏（小于 768）面板改到内容下方并占满宽度。

结构：标题和关闭、可滚动正文、底部吸底「取消 / 保存」。取消放弃修改并关闭。有未保存修改时，切换节点、关闭、离开页面都要确认（文案：「有未保存的修改。离开后这些修改会丢失。」）。数据路由下用 `useBlocker`；测试里的 `MemoryRouter` 没有 data router，守卫在那种环境下不挂载，关闭和切换仍走确认框。

需求抽屉、Agent 追踪仍用 `ReadingDrawer`（遮罩抽屉）。需求抽屉补上同一条吸底保存栏。

### 3.4 模型节点面板 `NodePanel`

替换 `NodeDrawer`。图谱（以及列表）右侧停靠该面板；点另一个节点换内容，图谱仍可平移缩放。图谱高度改为撑满视口（`calc(100vh - 260px)`，最小 420）。

页签：

- 实体：基本信息 / 字段 / 关系 / 条件与状态 / 被引用
- 动作：基本信息 / 输入输出 / 前置条件与效果 / 被引用

基本信息：名称、分组、描述（实体的 label 用「描述」，不再是 `description`）、代码位置。动作另有「用途」和绑定的 API（只改本地草稿）。

集合全部用 `EditableTable`：字段、输入、输出、条件、状态、约束、前置条件、效果。输入的 label 是「输入参数」。相关边（执行者 / 对象 / 引用）放在「被引用」页，同样行内编辑，和实体关系分开。

关系行写成一句话的控件：[源实体] [正向名称] [目标实体] （基数）。展开行里是反向名称、API 名称、外键、必填、描述。

图谱开启拖线：两端都是实体时，在源实体的关系页追加一条草稿；否则追加一条边（默认角色：指向动作用「执行者」，否则「对象」）。页头「新建关系」在已经打开实体面板时也是追加一行；关系页签和没有打开实体时仍用 `LinkEditor` 对话框（md），不再叠在面板上。

`data_schema` 放到折叠的「高级」里，只读，保存时不提交。

**一次保存。** 点「保存」才按顺序提交：`PATCH` 节点（名称、描述、分组、代码位置、属性、动作的输入输出和规则）、API 绑定有变化再 `PUT`、字段 / 关系 / 边按草稿增删改。从已绑定 API 填充或重建只改草稿（用已加载的 API 字段表按名称合并或替换，空的用途和格式一并补上），随这次保存写入，不再立刻调用 `/io/from-apis`。删掉「编辑后请点击右上角保存」。删除节点仍是标题栏里的独立动作，被引用时沿用二次确认。

被引用的类型显示中文：边、关系、API、需求、用例。

## 4. 推广到其他页面

- **API 注册表**：去掉「编辑」和「编辑描述和字段」两个对话框。点一行或「添加」打开同一块停靠面板：基本信息 / 输入输出 / 高级。高级里的请求、响应 JSON 只读。一次「保存」写入基本信息和字段表（后端按字段写回模式并保留已有约束）。从 OpenAPI 导入仍是 `sm` 对话框。
- **需求抽屉**：基本信息、人员、结构合成底部一个「保存」。标题栏保留「AI 结构化」和「确认」（确认是状态流转，不是保存）。关联用例改为「关联用例」。
- **新建任务**：名称、类型、执行者、环境补上标签。策略深度的存库值仍是 `light` / `standard` / `thorough`，界面显示轻量 / 标准 / 充分。
- **执行列表**：补上被测系统、版本筛选；不选就是全部系统。文案里的策略入口改到任务路由。
- 其余新建、编辑对话框改走 `AppModal` 的三档宽度。英文界面文案改为简体中文（`Add/Edit`、`Linked cases`、`DB column`、`Version ${v}`、`Choose …`、自动化脚本复选框、`without script` 等）。演示数据和种子内容不改。

## 5. 明确不做

- 不改 `progress()` 的步骤键和完成条件，不改部署文件。
- 不实现全局编号查找（原 NAV-015 里的另一半）。
- 不实现 UX-009 的悬停查代码、改名和跨系统引用，UX-010 的页头省略，FLOW-011 的引导手册。本轮只让菜单顺序和主流程对齐，并在面板里用可读名称显示引用。
- 不把模型建议从版本页搬走。
